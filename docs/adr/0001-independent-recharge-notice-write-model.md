# 0001. 充值待办使用独立写模型和统一收件箱读模型

Date: 2026-08-07

## Status

Accepted

## Context

教练需要向管理员上报会员充值事项。它不需要管理员录取为正式课程，也不能直接证明充值已经入账，但管理员仍需在处理课程填报的同一入口看到它。

把它编码成一种课程类型会让课程录取、课时统计、消费和真实充值边界变得含糊；把它完全放到独立页面，又会增加管理员漏看的风险。

## Decision

充值待办使用独立的 `coach_recharge_notice` 写模型，不能写入正式课程、消费、课程会员或真实充值记录。管理员默认收件箱通过统一只读模型混合待审课程和待知悉充值；不同类型继续调用各自的状态转换接口。

管理员“已知悉”只确认当前内容版本。教练修改已知悉内容时增加版本并重新进入待处理；知悉操作按版本条件更新，且不改变内容更新时间。

## Consequences

- 课程和真实充值的既有状态机、统计及接口保持不变。
- 管理员获得一个按业务日期和上报时间排序的统一待处理入口。
- 跨类型分页需要联合读取索引，再批量装配各自 DTO。
- 已知悉历史永久保留，需要分页和日期范围查询控制展示规模。
- 发布必须先完成数据库迁移，再发布后端和两个客户端。
