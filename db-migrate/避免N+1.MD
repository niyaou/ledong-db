GORM模型转换和N+1查询优化方案
一、GORM模型转换
1.1 文件结构
在 internal/model/ 目录下创建以下文件：

1.2 关键转换规则
字段类型映射：

Java Long → Go uint64
Java float → Go float32 (保持原类型，Spend.description为float)
Java int → Go int
Java LocalDateTime → Go time.Time
Java Date → Go time.Time
关联关系映射：

@ManyToOne → gorm:"foreignKey:xxx_id"
@OneToMany → gorm:"foreignKey:xxx_id"
@ManyToMany → gorm:"many2many:table_name"
表名和列名：

使用GORM默认命名（驼峰转蛇形）或通过标签指定
注意：coach_id 在Coach表中作为主键字段名
二、N+1查询避免策略
2.1 优先级策略
第一优先级：使用 Preload（推荐）

适用于大多数场景
代码简洁，GORM自动处理批量查询
会执行2-3次查询（主查询 + 关联查询），但避免N次查询
第二优先级：使用 Joins（特定场景）

需要单表结果时（只查询关联表的少量字段）
需要自定义JOIN条件时
聚合查询场景（COUNT、SUM等）
2.2 各实体的N+1场景分析
Charge（充值记录）
关联： PrepaidCard, Coach
查询场景： 查询充值列表需要显示卡信息和教练信息
解决方案： db.Preload("PrepaidCard").Preload("Coach").Find(&charges)
Spend（消费记录）
关联： PrepaidCard, Course
查询场景： 查询消费列表需要显示卡信息和课程信息
解决方案： db.Preload("PrepaidCard").Preload("Course").Find(&spends)
Course（课程）
关联： Coach, Court, Spend, PrepaidCard(ManyToMany)
查询场景： 查询课程列表需要显示教练、场地、会员列表
解决方案： db.Preload("Coach").Preload("Court").Preload("Members").Find(&courses)
PrepaidCard（预付费卡）
关联： Charge, Spend, Course(ManyToMany)
查询场景： 查询卡列表需要显示充值记录、消费记录、关联课程
解决方案： db.Preload("Charges").Preload("Spends").Preload("Courses").Find(&cards)
三、实现要点
3.1 模型定义要点
外键字段： 必须在模型中定义外键ID字段（即使不需要直接访问）
关联标签： 正确配置 foreignKey、references、many2many 等标签
索引标签： 在外键字段添加 gorm:"index" 标签（与SQL索引对应）
中间表： ManyToMany关系通过 many2many:course_member 指定中间表
3.2 查询规范
标准查询模式：

// 列表查询 - 使用Preload
var courses []Course
db.Preload("Coach").Preload("Court").Find(&courses)

// 单个查询 - 使用Preload
var course Course
db.Preload("Coach").Preload("Court").Preload("Members").First(&course, id)

// 条件查询 - Preload放在最后
db.Where("start_time > ?", startTime).
   Preload("Coach").Preload("Court").
   Find(&courses)
避免的错误模式：

// ❌ 错误：会导致N+1查询
var courses []Course
db.Find(&courses)
for _, course := range courses {
    db.Model(&course).Association("Coach").Find(&course.Coach)
}
3.3 聚合查询优化（非N+1问题）
聚合查询（COUNT、SUM等）不是N+1问题，应该在数据库层面使用SQL聚合函数完成：

示例场景：

教练今年的课程数量
var count int64
yearStart := time.Date(time.Now().Year(), 1, 1, 0, 0, 0, 0, time.Local)
db.Model(&Course{}).
   Where("coach_id = ? AND start_time >= ?", coachID, yearStart).
   Count(&count)
// 执行：SELECT COUNT(*) FROM course WHERE coach_id = ? AND start_time >= ?
课程学员数（COUNT关联表）
var count int64
db.Table("course_member").
   Where("course_id = ?", courseID).
   Count(&count)
// 执行：SELECT COUNT(*) FROM course_member WHERE course_id = ?
所有学员消费的总数量（SUM + JOIN）
var total float32
db.Table("spend").
   Joins("JOIN course_member ON spend.prepaid_card_id = course_member.member_id").
   Where("course_member.course_id = ?", courseID).
   Select("COALESCE(SUM(spend.charge), 0)").
   Scan(&total)
// 执行：SELECT SUM(spend.charge) FROM spend 
//       JOIN course_member ON spend.prepaid_card_id = course_member.member_id
//       WHERE course_member.course_id = ?
聚合查询要点：

✅ 使用 Count()、Sum()、Select("SUM(...)") 等聚合函数
✅ 使用 Table() 直接操作表，避免加载实体
✅ 复杂聚合使用原生SQL或 Raw()
❌ 不要在循环中查询每条记录的关联数据再累加（这才是N+1）
3.4 性能优化建议
按需加载： 只Preload真正需要的关联，避免过度加载
使用Select： 如果只需要关联表的特定字段，使用 Preload("Coach", "id,name")
批量查询： 使用 Preload 时GORM会自动批量加载，无需额外处理
索引支持： 确保外键字段有索引（已在SQL中创建）
聚合查询： 直接在数据库层面完成，不要加载数据到应用层再计算
